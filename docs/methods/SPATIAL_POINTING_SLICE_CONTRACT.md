# Spatial Pointing-Slice Contract — `S_v -> U_v -> (R_a, R_b)`

**Status:** supporting contract for active V06/V08; blocking before task-derived one-dimensional pointing fibers become mechanism/workspace evidence
**Purpose:** preserve the construction in which a virtual universal joint is a task-derived one-dimensional pointing level set of a two-dimensional spherical-closure parent, not an arbitrary replacement for the virtual spherical joint.

> This contract no longer blocks V05. Active V05 studies the complete one-dimensional fixed-position fiber of a spatial 4R serial chain directly. This contract becomes active when V06/V08 construct one-dimensional children from a two-dimensional 5R pointing parent and remains mandatory before the deferred V10 all-family atlas.


## Core construction

At a fixed Cartesian task point `p`, close the manipulator to ground with a virtual spherical joint `S_v(p)`:

```text
6R + S_v -> M_position = 3
```

For the aligned-terminal special case, quotient the terminal roll generated by `R6` only after the terminal-roll eligibility and reconstruction conditions pass:

```text
(6R + S_v) / R6 -> 5R + S_v -> M_pointing = 2
```

The two-DOF parent describes position-fixed orientation behavior and, under the selected task projection, tool pointing. A one-DOF four-bar child requires one additional independent pointing constraint:

```text
F_c = { q in P_p : h(d(q)) = c }
```

with `dim(F_c)=1` at a regular value.

Only after the parent and level set are defined and validated may the virtual spherical closure be represented on that level set by a virtual universal joint:

```text
S_v --[explicit pointing level set]--> U_v
```

and the virtual universal joint may then be decomposed into its two perpendicular revolute coordinates:

```text
U_v(alpha, beta) = R_a(alpha) R_b(beta),    a perpendicular to b.
```

The research pipeline is therefore:

```text
Cartesian point p
  -> exact virtual S_v closure
  -> complete fixed-position parent
  -> aligned-roll quotient when eligible
  -> two-DOF pointing parent
  -> explicit scalar pointing constraint h(d)=c
  -> validated one-DOF U_v level-set fiber
  -> U_v = R_a R_b
  -> architecture-derived spatial four-bar family
  -> returned branch / component
  -> (w_a, w_b), angular coverage, singularity diagnostics
  -> defined mechanism predicate
  -> explicit reconstruction law
  -> independent source-chain coverage test
```

## `tool_a` and `tool_b`

`tool_a` and `tool_b` are not two separate four-bar mechanisms.

They are the two perpendicular revolute coordinates inside the same task-derived virtual universal joint:

```text
U_v(alpha, beta) = R_a(alpha) R_b(beta).
```

One continued one-DOF mechanism component produces both functions:

```text
alpha = alpha(s)
beta  = beta(s)
```

and therefore one solve produces both winding questions:

```text
W = (w_alpha, w_beta).
```

`tool_a` asks whether `R_a` circulates on that returned component.
`tool_b` asks whether `R_b` circulates on the same returned component.

Neither result alone establishes complete parent pointing coverage.

## Required parent/child equivalence checks

A `UXXX` mechanism is source-derived evidence only if its `U_v` can be traced to an explicit level set of the `S_v` parent.

Minimum checks:

1. **Parent dimension:** the fixed-position/pointing parent is regular and two-dimensional over the claimed region.
2. **Parent representation:** the parent exists independently of the selected one-dimensional slice.
3. **Explicit level set:** the scalar constraint `h(d)=c` and its task/architecture motivation are recorded.
4. **Rank reduction:** the scalar constraint reduces the parent to a regular one-dimensional level set at the tested points.
5. **Tangent equivalence:** the null tangent of the `U_v` closure agrees with the constrained-parent tangent after coordinate lifting.
6. **Pointing equivalence:** parent level set and child produce the same tool-pointing curve within tolerance.
7. **Configuration reconstruction:** child configurations lift back to source-chain configurations satisfying the original fixed-position problem.
8. **Component/branch equivalence:** local agreement is not enough; the compared components remain equivalent over the interval used for winding/coverage claims.
9. **Limit correspondence:** joint limits and any coordinate periodicity map correctly.
10. **Provenance:** every research row records source chain, parent component, level-set constraint, virtual axes, and decomposition certificate.

A standalone `UXXX` geometry that passes closure and winding tests but lacks this provenance remains useful `mechanism_explorer_only` data, not workspace evidence.

## Interpretation of V04B/V04C `phi` sweeps

The arbitrary in-plane rotation

```text
(a,b) -> (a(phi), b(phi))
```

used in V04B/V04C is a diagnostic sensitivity experiment.

It established that winding can depend strongly on the chosen virtual-`U` representation. That is evidence that the `S_v -> U_v` construction must be defined from the source task and level set.

Until a mapping is proved between `phi` and a legitimate family of pointing constraints/level sets:

```text
phi is NOT automatically a physical atlas parameter.
```

V04B/V04C results remain useful diagnostics about coordinate sensitivity and symmetry. Arbitrary `phi` variants must not be mixed into a source-derived corpus as though they were independent physical mechanisms.

## Animation / visualization contract

V03/V04C GIFs remain useful mechanism-closure demonstrations. Their canonical branches must be labeled:

```text
canonical local branch animation
param=s (not driven)
```

rather than as a driven `tool_a` mechanism.

Task-derived level-set animations should visibly include:

- the physical source manipulator;
- the tool point and virtual `S_v` center;
- the complete two-dimensional parent or a clear parent reference;
- tool pointing direction `d`;
- the level-set definition `h(d)=c`;
- the derived `R_a` and `R_b` axes;
- `alpha(s)` and `beta(s)` readouts;
- component identity;
- an explicit statement that continuation arclength `s`, not `tool_a`, is the branch parameter unless an input is prescribed.

### Acceptance by provenance

| Provenance | Required on branch animations |
|---|---|
| `mechanism_explorer_only` | Label **canonical local branch**; `param=s (not driven)`; chart axes may appear as readouts; no claim of a validated `S_v -> U_v` child. |
| `task_derived` | Show source manipulator, `S_v`, parent reference, pointing direction, level-set definition, derived axes, coordinate readouts, component identity, and branch parameter. |

## Evidence gate

Before a one-dimensional child can be used for mechanism-rule discovery or workspace reconstruction, require at least:

```text
slice_provenance = task_derived
parent_component_id = <recorded>
decomposition_status in {EXACT_GLOBAL, EXACT_ON_COMPONENT}
fiber_equivalence_status = PASS
```

Diagnostic standalone four-bars remain separate:

```text
provenance = mechanism_explorer_only
```

and must not be silently pooled with source-derived fibers.
