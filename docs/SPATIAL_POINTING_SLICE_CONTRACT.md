# Spatial Pointing-Slice Contract — `S_v -> U_v -> (R_a, R_b)`

**Status:** blocking research contract before V05 evidence generation
**Purpose:** preserve the original dexterity construction: the virtual universal joint is a task-derived one-DOF pointing fiber of the two-DOF spherical-closure parent, not an arbitrary replacement for the virtual spherical joint.

## Core construction

At a fixed Cartesian task point `p`, close the manipulator to ground with a virtual spherical joint `S_v(p)`:

```text
6R + S_v -> M_position = 3
```

For the aligned-terminal special case, quotient the terminal roll generated by `R6`:

```text
(6R + S_v) / R6 -> 5R + S_v -> M_pointing = 2
```

The two-DOF parent describes position-fixed tool pointing. A one-DOF four-bar fiber requires one additional independent pointing constraint:

```text
F_c = { q in P_p : h(d(q)) = c }
```

with `dim(F_c)=1` at a regular value.

Only after that fiber is defined and validated may the virtual spherical closure be represented on the fiber by a virtual universal joint:

```text
S_v --[explicit pointing slice]--> U_v
```

and the virtual universal joint may then be decomposed into its two perpendicular revolute coordinates:

```text
U_v(alpha, beta) = R_a(alpha) R_b(beta),    a perpendicular to b.
```

The research pipeline is therefore:

```text
Cartesian point p
  -> virtual S_v at tool point
  -> aligned-roll quotient
  -> two-DOF pointing parent
  -> explicit scalar pointing constraint h(d)=c
  -> validated one-DOF U_v fiber
  -> U_v = R_a R_b
  -> ordered spatial four-bar family
  -> returned branch
  -> (w_a, w_b), angular coverage, singularity diagnostics
  -> Grashof-like / atlas predictor
  -> later dexterity test
```

## `tool_a` and `tool_b`

`tool_a` and `tool_b` are not two separate four-bar mechanisms.

They are the two perpendicular revolute coordinates inside the same task-derived virtual universal joint:

```text
U_v(alpha, beta) = R_a(alpha) R_b(beta).
```

One continued one-DOF mechanism branch produces both functions:

```text
alpha = alpha(s)
beta  = beta(s)
```

and therefore one solve produces both winding questions:

```text
W = (w_alpha, w_beta).
```

`tool_a` asks whether `R_a` circulates on that returned fiber.
`tool_b` asks whether `R_b` circulates on the same returned fiber.

## Required fiber-equivalence checks

A `UXXX` mechanism is **dexterity-derived evidence** only if its `U_v` can be traced back to an explicit pointing fiber of the `S_v` parent.

Minimum checks:

1. **Parent dimension:** the position-and-pointing parent is regular and two-dimensional.
2. **Explicit slice:** the scalar constraint `h(d)=c` is recorded and reduces the parent to a regular one-dimensional fiber.
3. **Tangent equivalence:** the null tangent of the `U_v` closure agrees with the tangent of the constrained `S_v` parent after coordinate lifting.
4. **Pointing equivalence:** both constructions produce the same tool-pointing curve, within tolerance, over the continued branch.
5. **Branch equivalence:** local agreement is not enough; the compared branches must remain equivalent over the interval used for winding / coverage claims.
6. **Provenance:** every research atlas row records which parent, slice constraint, and virtual axes generated the child four-bar.

A standalone `UXXX` geometry that passes closure and winding tests but lacks this provenance remains useful **mechanism-explorer data**, not yet evidence for dexterous-workspace characterization.

## Interpretation of V04B / V04C `phi` sweeps

The arbitrary in-plane rotation

```text
(a,b) -> (a(phi), b(phi))
```

used in V04B/V04C is a diagnostic sensitivity experiment.

It established that winding can depend strongly on the chosen virtual-`U` representation. That is evidence that the `S_v -> U_v` construction must be defined from the pointing task.

Until a mapping is proved between `phi` and a legitimate family of pointing constraints / fibers:

```text
phi is NOT automatically a physical atlas parameter.
```

V04B/V04C results may be retained as diagnostic evidence about coordinate sensitivity and symmetry, but arbitrary `phi` variants must not be mixed into the V05 dexterity-derived corpus as though they were independent physical mechanisms.

## Animation / visualization contract

The V03 GIFs remain useful closure demonstrations, but their current canonical branches can visually appear dominated by `tool_alpha`.

They must be labeled as:

```text
canonical local branch animation
```

not as a driven `tool_a` mechanism.

Future task-derived fiber animations should visibly include:

- the tool point and virtual `S_v` center;
- tool pointing direction `d`;
- the derived `R_a` and `R_b` axes;
- the pointing-slice definition / curve;
- `alpha(s)` and `beta(s)` readouts;
- a clear statement that continuation arclength `s`, not `tool_a`, is the branch parameter unless an input is explicitly prescribed.

## V05 evidence gate

Before an all-family row can be used for descriptor mining or a Grashof-like hypothesis, require:

```text
slice_provenance = task_derived
fiber_equivalence_status = PASS
```

Diagnostic standalone four-bars may still be stored, but must use a separate provenance such as:

```text
mechanism_explorer_only
```

and must not be silently pooled with task-derived fibers.
